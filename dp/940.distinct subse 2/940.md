## Recusive Approach

### Key Insight
2 option- pick or not pick

### Algorithm

1. params for the recursive function- id, ctr, ip string s, size of s, non dupe subsequences arr called ans, each subsequence called smol
2. base case- id>=n
      a. initialise a flag exists. set it to false.
      b. for each subsequence in ans, compare it to our curr subseqquence smol. //finding smol in ans.
           - if matches, mark exists to true.
           - break out of the loop.
      c. if smol doesnt exist in ans, 
           - inc cnt
           - add smol to ans
           - set exists to false
3. take
4. not take
5. in the main fx, initialise all the params and call recursive function.
6. cnt is also counting the emepty subsequence so return cnt-1.

### Why it works

looking at all the subsequences but only inc ctr for unique ones.

## ⏱ Complexity

| Time | Space |
|------|-------|
| `O(n.2^n)` | `O(n.2^n)` |

total num of subsequences = 2^n
recusrsion depth= n
space- recusion stack and ans arr
time- o(n) for building strings
    - O(2^n) for the linear searches across ans
    - O(2^n) subsequences

##  Takeaways

- TLE lol 
- when calling further recursions, id++ causes stack overflow, ++id skips some ids. use id+1 only.
- pass everything by reference except id, as every recusion call needs their own ids so changing in one call wont change it in the entire function.
